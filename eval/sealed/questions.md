# 봉인 시험 문항 (30문항)

Agent를 만드는 동안에는 이 문항으로 점수를 재지 않는다. 다 만든 뒤 한 번만 돌린다.
기업과 공시는 `eval/sealed/draw.py`가 고정된 씨앗(20261006)으로 뽑았다. 모집단은 DB의 관계가 아니라 공시 목록과 기업 원장이다.

## 확인하는 법

1. 링크를 열어 DART 원문을 본다.
2. "정답 초안"이 원문과 같으면 확인 칸에 ○, 다르면 × 와 함께 원문의 값을 적는다.
3. 초안은 DB에서 나온 값이다. 초안이 틀렸다면 그것이 이 시험이 찾아야 하는 것이니, 고치지 말고 그대로 적어 주면 된다.

정답 초안이 틀린 것으로 드러나 추출기를 고치게 되면, 그 문항은 "개발에 쓴 문항"으로 표시하고 점수에서 따로 센다.

## 원문 대조 상태 (2026-10-08)

Claude가 추출기를 거치지 않고 원자료를 직접 읽어 30문항을 한 번 대조했다. 사람이 본 것만큼 강한 근거는 아니다.

- 읽은 것: 공급계약·취득처분 공시는 캐시에 있는 DART 원문의 칸, 공시가 없는 문항은 공시 목록, 지분은 OpenDART API 응답 원본, 계열은 계열회사 표의 상장여부 칸
- 초안과 달라 고친 문항 2개: **S23**(금호에이치티 6.49% → 7.06%. 두 회사의 공시가 서로 다르다), **S27**(상장 계열사 "없음" → 해외 상장 1곳)
- 빈칸을 채운 문항 3개: S01·S14(계약·처분한 자회사 이름), S11(대상 회사 이름)
- 초안 그대로인 문항: 나머지 25개. S13과 S15의 이상해 보이던 이름은 원문에 그렇게 적혀 있었다
- 사람이 직접 볼 문항(): 고친 2개 S23, S27 + 무작위 5개. 지분·계열 문항(S21~S30)은 API 응답과만 대조했고 사업보고서 본문은 열지 않았다
