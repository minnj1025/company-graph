# 6판 결과 — 시각화 카드를 알맞게 고르는가

문항은 Claude 하위 작업이 썼고, 채점은 기계적이다(`python -m eval.v6.score`). 답을 쓴 모델은 claude-haiku-5-5(사이트와 같은 모델).

채택 기준: 카드가 필요한 질문 14개 중 80% 이상에서 알맞은 카드를 띄우고, 필요 없는 질문 6개 중 카드를 띄운 것이 1건 이하. 이 기준은 실행 전에 정했지만 저장소에는 문항과 함께 커밋하지 못하고 이 결과와 함께 적는다.

## 1차 (2026-10-20, 카드를 `show_view` 라는 별도 도구로 띄울 때)

| | 결과 | 기준 |
|---|---|---|
| 카드가 필요한 질문 14개 중 알맞은 카드 | 3 (21%) | 80% 이상 — 미달 |
| 카드가 필요 없는 질문 6개 중 카드를 띄운 것 | 0 | 1건 이하 — 통과 |
| 비용 | 20건 $0.123 | |

- 맞힌 3건: V01 지분 구조(ownership), V03 계열 상장사와 시총(group), V12 계약 기간(contracts).
- 틀린 11건은 모두 카드를 아예 띄우지 않은 경우다. 엉뚱한 종류를 고른 경우는 없었다.
- 같은 답에서 그래프 도구(`show_on_graph`)는 14건 중 13건에서 불렀다. 지시문의 "답을 쓰기 전에 부른다"는 규칙은 그래프 도구에서는 지켜지는데, 그 옆에 하나 더 둔 카드 도구는 거의 잊었다.
- 카드 대신 답 안에 표를 그렸다(V04 계열사 12곳 표, V14 수익률 표 등).

### 원인과 고친 것

답을 쓰기 직전에 부르는 도구가 둘이면 작은 모델은 익숙한 하나만 부른다. 카드를 따로 부르게 하지 않고, 이미 거의 매번 부르는 `show_on_graph` 에 `views` 칸(카드 둘까지)을 붙였다. 그래프에 무엇을 보일지 정하는 그 자리에서 카드도 함께 정하게 했다. `show_view` 는 Agent의 도구 목록에서 빼고, `/api/view` 가 쓰는 함수로만 남겼다.

이 수정은 1차 결과를 보고 한 것이므로 2차 점수는 "문항을 보고 고친 점수"다.

## 2차 (2026-10-20, 카드를 `show_on_graph` 의 `views` 로 띄울 때) — 문항을 보고 고친 점수

결과 폴더: `agent/claude-haiku-5-5-fold`. 채점: `python -m eval.v6.score claude-haiku-5-5-fold`

| | 1차 | 2차 | 기준 |
|---|---|---|---|
| 카드가 필요한 질문 14개 중 알맞은 카드 | 3 (21%) | 13 (93%) | 80% 이상 — 통과 |
| 카드가 필요 없는 질문 6개 중 카드를 띄운 것 | 0 | 1 | 1건 이하 — 통과 |
| 비용 | $0.123 | $0.121 | |

- 틀린 것: V02(카카오의 주주와 출자 대상)는 그래프 도구도 카드도 부르지 않고 답을 썼다. V15(삼성전자 최대주주가 누구야)에 지분 구조도를 띄웠다. 값 하나로 끝나는 질문이지만 지분 구조를 함께 보여 준 것이라 해가 크지는 않다.
- 함께 띄운 카드: V01 지분 구조도에 계열 지도, V08 연결 경로에 지분 구조도. 둘 다 문항이 허용한 조합이다.
- 4건(V06, V07, V10, V12)은 첫 호출에서 `as_of`, `company_id` 를 `views` 밖에 적어 인자 오류가 났고, 다음 차례에 고쳐 다시 불렀다. 카드는 한 번만 떴지만 한 차례를 낭비했다. 그래서 `show_on_graph` 가 밖에 적힌 두 값을 카드의 기본값으로 받게 고쳤다(이 수정 뒤에는 다시 돌리지 않았다).
- 카드의 대상 회사는 채점하지 않았지만 기록을 보면 카드를 띄운 15건 모두 질문의 회사였다.
