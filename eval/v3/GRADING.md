# 평가 문항 3판 — 답을 채점하는 규칙

답을 쓴 쪽과 다른 채점자가, 정답과 답만 보고 판정한다. 글자가 같은지 견주지 않고 읽어서 판정한다.

## 판정 네 가지

| 판정 | 뜻 |
|---|---|
| `correct` | `must_include` 의 회사와 값이 모두 있고, `must_not` 의 회사를 만드는 회사나 주력으로 내놓지 않았다 |
| `partial` | `must_include` 의 일부만 있다. 또는 회사는 맞는데 물은 값(매출 비중)이 빠졌다. 틀린 사실은 없다 |
| `unanswered` | 찾지 못했다고 답했다. 틀린 사실을 내놓지 않았다 |
| `wrong` | `must_not` 의 회사를 만드는 회사나 주력으로 답했다. 또는 값이 정답과 다르다 |

## 세부 규칙

1. **표기 차이는 같은 값이다.** SK아이이테크놀로지 = 에스케이아이이테크놀로지 = SKIET. 90.6% = 90.6 = 약 91%.
2. **`must_not` 의 회사를 언급만 한 것은 틀린 것이 아니다.** "장비를 만드는 회사라 제외했다", "보고서에 언급만 있다"처럼 맞게 구분했으면 감점하지 않는다.
3. **`others` 와 `accept` 에 있는 것은 덧붙여도 감점하지 않는다.**
4. **정답에 없는 회사를 덧붙인 경우**: 정답만으로는 맞는지 알 수 없다. 판정에는 넣지 않고 `extra` 에 그 회사 이름을 적는다(나중에 원문과 따로 대조한다).
5. **맞는 값과 틀린 값을 함께 냈으면** 묻는 핵심이 틀렸는지 본다. 핵심이 틀리면 `wrong`, 곁가지가 틀리면 `partial`.
6. 이어지는 대화 문항(`F`로 시작)은 둘째 질문의 답만 판정한다. 가리키는 대상("그중", "그 회사")을 잘못 잡았으면 `wrong`.

## 출력

`eval/v3/grades/<묶음>.json`:

```json
[{"key": "…", "verdict": "correct | partial | unanswered | wrong", "reason": "한 문장", "extra": ["정답에 없는데 답에 나온 회사"]}]
```
