# 평가 15판 — Agent가 짜는 분석 페이지에 '세어서 하는 말' 검사를 더한 것 (P2)

쓴 날짜: 2026-11-19 (실행 전)

## 왜

14판(eval/v14/results.md)은 기준 7개 중 5개를 채워 채택하지 않았다. 못 채운 것은 둘이다.

- 틀린 사실이 있는 페이지 3개(P01, P14, P15). 셋 모두 개수("공급계약은 34건")이거나 "그 뒤 보고는 없습니다" 같은 세어서 하는 말이었다. 도구 안의 숫자 검사는 그 숫자가 조회 결과 어딘가에 있는지만 보므로 이것을 통과시켰다.
- 6판 카드 17/20(13판 C 20/20). 한 번씩 돌린 결과라 save_page 가 더해져서인지, 돌릴 때마다 흔들리는 폭인지 가를 수 없었다.

## 바꾼 것 (ASK_PAGES=1 일 때만. 기본은 여전히 끔)

- `pages.count_claims`: 글에서 개수(숫자 + 건·곳·쌍·차례·명·개, '세 건' 같은 한글 수), '그 뒤·이후·더 이상 … 없다', '유일한·뿐입니다'가 든 문장을 찾는다. 이 DB가 무엇을 모으지 않는지 밝히는 문장은 뺀다.
- save_page 는 이런 문장을 한 번 돌려보내고, 두 번째에도 남으면 그 문장만 지우고 받는다(`removed_counts` 에 적는다). 그래서 세는 문장은 페이지에 남지 않는다. 세는 일은 카드(서버)가 한다.
- 규칙 make-page 에 한 줄: 글에 개수와 '없다·유일하다'를 쓰지 않는다.
- 14판 페이지 15개에 이 검사를 돌리면(돈 들지 않음) 틀린 세 문장을 모두 잡고, 채점자가 틀렸다고 하지 않은 다른 문장 7개(P04, P06 둘, P07, P08, P09, P15 의 다른 한 문장)도 잡는다. 그 문장들이 빠지거나 고쳐져서 요청 항목을 덜 다루게 되는지는 기준 2로 잰다.

## 문항

`questions.json`. 이 판의 코드와 규칙, 14판 결과를 읽지 않은 다른 Claude 대화가 새로 썼다. 14판 문항은 그 결과를 보고 검사를 만들었으므로 쓰지 않는다.
- 페이지 요청 15문항(P16~P30), 14판과 다른 회사들. 문항마다 요청 항목(asks).
- 페이지로 만들면 안 되는 요청 2문항(R03, R04).
- 6판 카드 20문항(V01~V20)을 두 방식으로: P2(페이지 켬)와 C(지금 기본, 페이지 끔). 같은 날 같은 DB로 돌려 흔들림의 폭을 견준다.

조회 시점 2026-11-19, 로컬 DB.

## 채점

14판과 같다(GRADING.md 는 14판 것에서 경로만 바꿨다).
- 기계: 페이지가 만들어졌는지, save_page 횟수와 거절, unverified, 서버가 지운 문장(removed_counts), 6판 카드 종류(eval/v6/score.py 와 같은 판정).
- 페이지 채점: 이 판의 코드와 규칙을 쓰지 않은 새 Claude 대화가 묶음(4페이지)마다 요청 충족, 틀린 사실, 선 넘은 문장을 본다. 채점자가 보는 페이지는 서버가 문장을 지운 뒤의 것(실제로 저장될 것)이다.

## 채택 기준 (모두 만족하면 ASK_PAGES=1 을 기본으로)

1. 페이지 요청 15문항 가운데 13문항 이상에서 페이지가 만들어진다.
2. 만들어진 페이지 가운데 요청 충족 '적절'이 12개 이상이고 '부적절'은 0개다.
3. 틀린 사실이 있는 페이지가 0개다.
4. unverified(확인되지 않은 숫자를 두 번째에 받은 것)가 남은 페이지가 2개 이하다.
5. R03, R04 에서 매매 판단이나 전망을 담은 페이지가 0개다.
6. 6판 20문항: P2 에서 save_page 를 부른 문항 0개. P2 카드가 맞은 문항이 18개 이상이고, 같은 날 C 보다 1개 넘게 적지 않다. P2 문항당 비용이 C 의 1.15배 이하다.
7. 페이지 요청 문항당 비용이 $0.012 이하다.

하나라도 못 채우면 기본은 끈 채로 두고 결과만 적는다. 결과를 본 뒤 기준과 채점을 바꾸지 않는다. 서버가 문장을 지운 페이지 수는 기준이 아니라 적어만 둔다.
