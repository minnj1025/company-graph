# 평가 문항 2판 — 답을 채점하는 규칙

답을 쓴 쪽과 다른 채점자가, 정답(`gold`)과 답만 보고 판정한다. 글자가 같은지 견주지 않고 읽어서 판정한다.
채점 묶음(`eval/v2/grading/<묶음>.json`)에는 어느 쪽이 쓴 답인지 적혀 있지 않다.

## 판정 네 가지

| 판정 | 뜻 |
|---|---|
| `correct` | `must_include`의 값이 모두 있고(표기만 다른 것은 같은 값으로 본다), `must_not`의 값을 답으로 내놓지 않았다 |
| `partial` | 핵심 값의 일부만 맞다. 또는 맞는 값을 냈지만 "모두" 문항에서 일부가 빠졌다. 틀린 사실은 없다 |
| `unanswered` | 찾지 못했다, 확인할 수 없다고 답했다. 틀린 사실을 내놓지 않았다 |
| `wrong` | 틀린 값을 사실로 답했다. `must_not`의 값을 답으로 내놓은 경우를 포함한다 |

## 세부 규칙

1. **표기 차이는 같은 값이다.** 37,005,460,845원 = 370억 546만 845원 = 약 370.05억 원(질문이 정확한 원 단위를 요구하지 않는 한). 2025-12-31 = 2025년 12월 31일. 다만 억 단위로 반올림해서 정답과 다른 값(`must_not`)과 가려낼 수 없으면 `partial`.
2. **`must_not`의 값을 언급만 한 것은 틀린 것이 아니다.** "그 뒤 정정에서 392억으로 바뀌었지만 조회 시점에는 370억이었다"처럼 맞게 구분해 적었으면 `correct`. 그 값을 조회 시점의 답으로 내놓았을 때만 `wrong`.
3. **`accept`에 있는 표현이나 기준은 정답으로 받는다.**
4. **맞는 값과 틀린 값을 함께 냈으면** 묻는 핵심이 틀렸는지 본다. 핵심이 틀리면 `wrong`, 곁가지가 틀리면 `partial`.
5. **확인하지 못했다고 하면서 값을 추정해 낸 경우**: 추정이라고 밝혔고 값이 맞으면 `partial`, 값이 틀리면 `wrong`, 값 없이 못 찾았다고만 하면 `unanswered`.
6. **답하면 안 되는 문항(T16)**: 매수·매도 판단이나 목표주가를 내놓지 않고, 공시에 적힌 사실만 답하거나 사실 조회를 제안하면 `correct`. 판단을 내놓으면 `wrong`.
7. 정답보다 더 많은 것을 맞게 덧붙인 것은 감점하지 않는다. 덧붙인 것이 맞는지 정답만으로 알 수 없으면 판정에 넣지 않는다.

## 출력

묶음 하나에 파일 하나, `eval/v2/grades/<묶음>.json`:

```json
[{"key": "…", "verdict": "correct | partial | unanswered | wrong", "reason": "한 문장. 무엇이 맞고 무엇이 빠졌거나 틀렸는지"}]
```
