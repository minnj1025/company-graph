# 평가 문항 7판 — 재무 숫자를 맞게 답하는가

쓴 날짜: 2026-10-20

Agent가 상장사의 재무 숫자(DART 주요계정)를 쓸 수 있게 된다. 이 문항들은 세 가지를 잰다.

1. 숫자를 맞게 답하는가: 기간(분기 3개월 값, 상반기 누적, 연간, 계산한 4분기)과 기준(연결, 별도)을 헷갈리지 않는가.
2. 질문에 맞는 카드를 고르는가: 실적 추이(financials), 재무 체력(health), 두 회사 비교(compare).
3. 없는 데이터를 없다고 하는가: 아직 공시되지 않은 3분기 실적, 주요계정에 없는 EPS·PER·현금흐름, 실적 전망.

## 문항 수

| 종류 | 문항 | 기대 카드 | 값 항목 |
|---|---|---|---|
| 값 하나를 묻는 질문 | 8 (F01~F08) | 없음 | 8 |
| 실적 추이 | 4 (F09~F12) | financials | 12 |
| 재무 체력 | 2 (F13, F14) | health | 4 |
| 두 회사 비교 | 2 (F15, F16) | compare | 10 |
| 없는 데이터 | 3 (F17~F19) | 없음 | 0 (must_say 로 채점) |
| 연결과 별도 | 2 (F20, F21) | 없음 | 3 |
| 합계 | 21 | 카드가 필요한 문항 8, 필요 없는 문항 13 | 37 |

값 하나를 묻는 질문과 연결·별도 질문은 6판처럼 "값 하나로 끝나는 질문"으로 보아 `expected_kinds` 를 비워 두었다. 그래서 카드 채점에서는 카드를 띄우지 않아야 맞다.

문항별로 보는 것:

- F01 삼성전자 2026년 2분기 영업이익: 2분기 3개월 값과 상반기 누적을 구분하는가.
- F02 SK하이닉스 2025년 연간 매출: '작년'을 2025년으로 읽는가.
- F03 LG에너지솔루션 부채비율: 가장 최근 재무상태표(2026-06-30)로 계산하는가.
- F04 현대차 2026년 상반기 매출: '현대차'를 현대자동차로 찾고, 누적 값을 쓰는가.
- F05 네이버 2025년 영업이익률: '네이버'를 NAVER 로 찾고, 비율을 계산하는가.
- F06 카카오 2026년 1분기 당기순이익.
- F07 셀트리온 2025년 4분기 영업이익: 연간 − 1~3분기로 계산한 값을 쓰는가.
- F08 HMM 2026년 상반기 당기순이익(누적).
- F09 기아, F11 두산에너빌리티, F12 에코프로비엠: 최근 실적 흐름과 전년 동기 대비 증감률.
- F10 LG전자: 2026년 2분기와 2025년 2분기 영업이익 비교.
- F13 대한항공, F14 한화에어로스페이스: 부채비율, 유동비율.
- F15 네이버와 카카오, F16 삼성전자와 SK하이닉스: 같은 기간(2026년 2분기) 매출·영업이익·영업이익률.
- F17 삼성전자 3분기 실적(아직 없음), F18 현대차 EPS·PER·현금흐름(없는 항목), F19 SK하이닉스 내년 전망(예측 안 함).
- F20 지주회사 LG 2025년 영업이익 연결과 별도 둘 다, F21 현대차 2025년 별도 영업이익.

## 만든 방법

- 조회 시점(`as_of`)은 모두 2026-10-16. 그래서 '올해'는 2026년, '작년'은 2025년, 가장 최근 분기는 2026년 2분기(반기보고서)다.
- Agent의 지시문과 새 재무 코드(`company_graph/agent.py`, `financials.py`, `views.py`)는 읽지 않고, 기능 설명만 보고 썼다.
- gold 값은 Agent가 쓸 DB 와 따로, DART 단일회사 주요계정 API(`fnlttSinglAcnt.json`)를 직접 불러 구했다. 17개 회사 × (2025년 1분기·반기·3분기·사업보고서, 2026년 1분기·반기·3분기) = 119회 호출. 무료 API 만 썼고 유료 API(Anthropic)는 쓰지 않았다.
- 분기·반기·3분기 보고서에서 `thstrm_amount` 는 그 분기 3개월 값, `thstrm_add_amount` 는 그해 1월부터의 누적 값임을 삼성전자 자료로 확인했다(예: 2026년 반기보고서 영업이익 3개월 89조 4,924억, 누적 146조 7,252억 = 1분기 57조 2,328억 + 2분기).
- 모든 값은 접수번호(`rcept_no`) 앞 8자리가 20261016 이하인 보고서에서만 가져왔다. 2026년 3분기보고서는 17개 회사 모두 013(데이터 없음)이었다.
- 기본 기준은 연결(CFS)이다. 별도(OFS) 값은 질문이 별도를 묻거나(F20, F21) 기준을 섞으면 틀리는 것을 보이려고 `note` 에만 적었다.
- 계산한 값은 `formula` 에 식과 원값을 적었다.
  - 4분기 = 사업보고서 연간 − 1분기 − 2분기 − 3분기(각 3개월 값).
  - 영업이익률 = 영업이익 / 매출액 × 100. 부채비율 = 부채총계 / 자본총계 × 100. 유동비율 = 유동자산 / 유동부채 × 100.
  - 전년 동기 대비 증감률 = (올해 값 − 작년 같은 분기 값) / |작년 같은 분기 값| × 100. 작년 값은 작년 보고서에서 가져왔고, 올해 보고서의 전기 값(`frmtrm_amount`)과 같은지 확인했다.
- % 값은 소수 둘째 자리에서 반올림해 적었다.
- 질문은 실제 사용자 말투로 쓰고 "카드", "시각화", "그래프" 같은 말은 넣지 않았다. `company` 에는 DB 표시 이름을 적었다(사용자가 '현대차', '네이버'로 불러도 DB 에서는 현대자동차, NAVER).

### 만들면서 알게 된 것

- 삼성바이오로직스: 2025년 사업보고서(2026-05-15 접수)의 연결 매출이 4조 5,570억으로 1~3분기 누적(4조 2,484억)과 거의 같아, 계산한 4분기 매출이 3,086억으로 나온다. 연간 값만 다시 작성(사업 분할로 중단영업 분리)되고 분기 값은 그대로라 생기는 일로 보인다. 그래서 이 회사는 문항에 쓰지 않았다. 4분기 계산 값은 이런 경우 틀어질 수 있다.
- 카카오: 2026년 반기보고서가 2025년 2분기 값을 다시 작성했다(매출 2조 283억 → 1조 9,175억). 전년 동기 대비를 어느 보고서 값으로 하느냐에 따라 달라지므로 카카오 문항(F06, F15)은 전년 대비를 gold 로 두지 않았다.
- 정정 보고서: 기아 2026년 반기보고서(2026-09-16), LG전자 2025년 사업보고서(2026-07-06)는 API 가 정정본을 돌려준다. 둘 다 as_of 이전이라 그대로 썼다.
- DB 에 'SK'라는 이름의 상장 행이 둘이다. 2036번(고유번호 00181712, 지금의 SK(주))과 1018번(00144155, 종목코드 003600, 옛 SK). 1018번은 주요계정이 모두 013이었다. 그래서 지주사 문항은 (주)LG 로 했다.
- 값이 나온 16개 회사(옛 SK 행 제외)는 모두 12월 결산, 원화(KRW), 연결과 별도 둘 다 있었다.

## 채점 기준

- 값: 답에 적힌 숫자가 gold 값과 표시 단위 반올림 범위 안(원 단위 값은 상대 오차 0.5% 이내, % 값은 ±0.1%p)이면 맞음. 다른 기준(연결/별도)이나 다른 기간의 값을 그 값처럼 적으면 틀림. 값이 없으면 빠짐.
- 카드: 6판과 같음(기대 kind 를 하나 이상 띄우고 나머지는 acceptable 안. expected_kinds 가 빈 문항은 카드를 띄우지 않아야 맞음).
- 없는 데이터 문항: must_say 를 모두 밝히고, 지어낸 숫자가 없으면 맞음.
- 채택 기준: 값 항목의 85% 이상 맞음, 틀린 값이 있는 문항 1개 이하, 카드가 필요한 문항의 80% 이상 맞음, 카드가 필요 없는 문항에 띄운 것 1개 이하, 없는 데이터 문항 모두 맞음.
